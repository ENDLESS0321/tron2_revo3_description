# 双手及腕部相机安装方向调整（1.5.0）

在上一版模型的基础上，将左右两侧的手／法兰组件和腕部相机组件分别沿前臂纵向中心轴旋转 180°。
该轴在各自的 `wrist_roll_*_Link` 坐标系中为经过 `[-0.0317, 0, 0]` m 的局部 Z 轴，
与有驱动的 wrist-roll 关节轴不同。只修改 `left_adapter_mount`、`right_adapter_mount`、
`left_wrist_camera_reference_joint` 和 `right_wrist_camera_reference_joint` 四个固定关节的姿态。
安装根部位置、手与法兰之间的连接、相机内部变换、网格、驱动关节限位及头部相机均保持原样。

## 更新原因

目标桌面操作姿态为右手掌朝下、手指朝机器人面向的方向。此次调整安装方向，目的是让机械臂达到
该姿态时具有更大的关节限位余量；不改变物理关节限位。本次发布验证了安装几何，尚未定量证明
限位余量或可行域增大。需要针对新模型重新进行 IK 和碰撞评估；不同安装方向的旧评估不能作为
本版的验证结果。

## 旋转约定与保留的连接

下表对比 1.4.0 之前的安装变换与当前变换。RPY 使用 URDF 固定轴 X/Y/Z 约定：
`R = Rz(yaw) Ry(pitch) Rx(roll)`。在父级腕部 link 坐标系中左乘半圈旋转，
即 `R_new = Rz(pi) R_old`。旋转轴线经过安装根部，因此根部平移保持不变。
修改的是安装分支姿态，腕部驱动关节的轴、零位、名称和限位不变；左右分支保留各自的
link 和 mesh，不交换左右手。

| 关节 | 调整前 RPY（rad） | 当前 RPY（rad） |
| --- | --- | --- |
| `left_adapter_mount` | `-1.57079632679 0 1.57079632679` | `-1.57079632679 0 -1.5707963268` |
| `right_adapter_mount` | `-1.57079632679 0 -1.57079632679` | `-1.57079632679 0 1.5707963268` |
| `left_wrist_camera_reference_joint` | `1.57079632679 0 -1.57079632679` | `1.57079632679 0 1.5707963268` |
| `right_wrist_camera_reference_joint` | `1.57079632679 0 1.57079632679` | `1.57079632679 0 -1.5707963268` |

法兰根部平移仍为 `[-0.0317, 0, -0.0812]` m；相机根部平移仍为
`[-0.0317, -1.31006316906e-18, -0.0753]` m，极小的 Y 值也按确认文件原样保留。
左右手与法兰的固定关节平移均为 `[0, 0.023855, 0]` m，RPY 保持原样：
左侧 `[-1.57079632679, -1.57079632679, 0]`，右侧
`[-1.57079632679, 1.57079632679, 0]`。
下游手指关节链、相机机械及光学坐标变换完整保留。手部局部 +X 表示掌心法向，
局部 +Z 表示手指方向。在相同机械臂姿态下，此安装半圈旋转使掌心法向反向，手指方向保持不变。

## 限位余量与验证范围

对于角度为 q、上下限为 [lower, upper] 的旋转关节，角度余量可定义为
`min(q - lower, upper - q)`。固定安装方向改变后，同一个世界坐标手部目标可能需要不同的
机械臂关节组合，因此即使关节限位不变，达到该目标时的余量也可能改变。
“限位余量更大”是针对指定桌面操作姿态的设计目的，不表示所有关节、所有姿态都已证明改善。

本次检查全部资产哈希，加载两个 58 自由度模型，核对桌面 45 cm 高度差，并比较 URDF/MJCF
在零位和非零机械臂姿态下的安装位置与方向。确认模型的零位对比中，手基座位置误差小于
2.4e-13 m、手指方向误差小于 1.4e-11、掌心法向点积约为 -1、相机相对手的变换误差小于
6.5e-15。这些几何检查不代表任务成功。限位余量或可行域的定量对比，应对两版模型采用相同的
目标位置、掌心朝下／手指朝前约束、桌面及物体几何、关节限位和碰撞规则。
安装方向改变后，旧 IK 轨迹和相机世界外参需重新计算；相机内部坐标变换保持不变。

## RL 与仿真训练资产要求

用于 RL 和仿真训练时，**每侧法兰应简化为一个刚性 link、一个碰撞体**：
左右法兰分别各一个。派生的 `assets/assembly_rl_convex.urdf` 现已满足这一要求；
默认装配模型保留详细碰撞几何。
当前发布文件已有一个 `left_adapter_link` 和一个 `right_adapter_link`，
但每侧包含 **48 个 URDF collision 元素**，新训练 URDF 将每侧的这 48 个元素替换为一个凸碰撞网格。

保持各侧法兰与机械臂的安装变换、手与法兰的固定变换原样不变。只合并法兰的固定零件，
确保新凸包包住原碰撞几何，保留单位、总质量、质心和等效惯量；凸包可能填平孔洞和凹陷，
可继续使用原视觉网格。
不要跨越有驱动的机械臂或手指关节进行合并。满足单一碰撞体要求时，可采用单个凸碰撞网格
或经间隙验证的保守基本形状。仅拼接网格或启用 fixed-joint merging 不保证最终只有一个
碰撞体：仿真器导入及自动凸分解可能把一个 URDF collision 元素拆成多个 shape。

应检查导入后的仿真模型，而不只检查 XML：每侧法兰最终必须恰好为一个刚体／link 和一个
碰撞 shape。与装配参考模型对比手部位姿、关节限位、质量／惯量、桌面／物体／自碰撞间隙
以及代表性接触。粗略凸近似可能填平孔洞或凹陷，从而改变间隙，不能直接作为可行域增大的
证据。将派生训练 URDF 与碰撞资产的哈希绑定到训练配置，并针对该资产重新计算 IK 和碰撞
检查。默认装配模型继续作为详细几何参考。新训练模型已随本次发布提供；MuJoCo 导入验证
每侧法兰恰好一个碰撞 shape，其他仿真器仍需核对各自的导入结果。

## 已提供的单凸包训练模型（1.5.0）

加载 `assets/assembly_rl_convex.urdf` 即可使用法兰简化模型。它直接派生自原样默认文件
`assets/assembly.urdf`；默认装配文件的内容保持逐字节不变。每侧法兰本来已有一个刚性 link，
因此只把它的 48 个 collision 元素替换为一个元素，不删除 link 或 joint。
视觉几何、质量、质心、惯量、安装变换、世界原点和关节限位保持原样。

新网格分别为 `assets/meshes/adapter_rl/left_flange_convex.stl` 与
`assets/meshes/adapter_rl/right_flange_convex.stl`，单位为米。
生成脚本读取每侧法兰的全部 48 个碰撞网格，应用 mesh scale 和 collision origin 后，
将顶点统一到该法兰 link 坐标系，再对顶点集合计算一个凸包。
因为输出顶点已处于 link 坐标系，新 collision origin 设为单位变换。
左右法兰分别生成一个凸包，不是把两只机械臂包进同一个凸包。
每个输出均为闭合凸表面，包住输入的所有碰撞顶点，最大半空间外侧误差小于 1e-8 m。

安装依赖后，在仓库根目录重建和验证：

```bash
.venv/bin/python tools/build_flange_convex.py
.venv/bin/python -m unittest discover -s tests -v
```

`assets/flange_convex.json` 记录输入／输出哈希、网格哈希、碰撞元素数量、边界、凸包体积
及几何验证。MuJoCo 导入后仍有 58 个广义位置，每侧法兰恰好一个碰撞 shape。
结构检查验证变更只发生在法兰碰撞几何；默认文件哈希仍是确认的新 URDF 哈希。
重建脚本会重新生成训练文件和报告；若有意改变几何，还需更新 `assets/manifest.json`
校验信息，查看工具的资产完整性检查才能通过。

凸包会填平法兰孔洞和凹陷，因此虽然减少了碰撞 shape 数量，也可能扩大碰撞占据区域。
它不证明训练加速、可行域增大、抓取成功或物理稳定性；应使用这一训练资产重新检查间隙和
任务相关接触。默认 `scene.xml` 仍对应详细装配模型，要使用新凸包必须导入训练 URDF。
本次发布不提供简化的 MJCF 场景。
